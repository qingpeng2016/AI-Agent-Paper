# ARIS Research Desktop — 产品说明

> 本文档依据 **ARIS Desktop** 界面（Research workflows）整理，用于产品、设计、研发对齐。描述范围与当前桌面端展示 **一致**。

---

## 1. 产品概览

| 项 | 说明 |
|----|------|
| **产品名称** | ARIS Desktop |
| **副标题** | Research workflows |
| **产品类型** | 本地化科研 AI Agent **工作台**（桌面客户端） |
| **一句话** | 覆盖「选题 → 文献 → 实验 → 审查 → 写作 → 图表」的 **顶会导向** 科研全流程，强调 **可验证引用** 与 **人机协同**，而非代写/降重工具。 |
| **典型用户** | 攻读 ML/NLP 等方向的 **硕士、博士、高校/企业科研人员**，目标投稿 **NeurIPS / ICLR / ICML** 等顶会。 |

---

## 2. 产品定位与边界

### 2.1 做什么

- 在 **真实学术数据源** 约束下，辅助完成科研各阶段产出（想法、综述、实验计划、稿件、图表等）。
- 通过 **参考文献门禁**、**审计等级**、**人工检查点**，降低 **引用幻觉、断言不实、逻辑漏洞** 等致命风险。
- 用户是 **科研主体**；产品是 **高阶助手 + 工作流引擎**，关键节点可暂停等人确认。

### 2.2 不做什么

- 不定位为「论文降重 / 降 AI 率 / 排版急救」类工具。
- 不承诺绕过查重或替代作者学术责任。
- 未经验证的文献 **不得** 进入最终引用、BibTeX 或正文（系统强制）。

## 3. 信息架构（主导航）

### 3.1 当前论文（多篇稿件并行）

| 项 | 说明 |
|----|------|
| **位置** | 侧栏品牌区下方、模块导航上方 |
| **能力** | 侧栏下拉切换 `paper_manuscript`；在「我的论文」中编辑、归档与设为当前 |
| **作用** | 同一用户可同时推进多篇论文；各模块 **产出** 均归属 **当前选中论文** |
| **存储** | 工作区路径、Wiki、artifact 等由 **平台按稿件默认 provision**，用户无需填写 |

### 3.2 工作流模块（二级导航）

左侧为 **3 个一级阶段 + 9 个二级模块**（一级分组始终展开，不可折叠）：

| 一级 | 二级模块 | 模块 ID | 说明（产品层） |
|------|----------|---------|----------------|
| **选题与实验** | 选题发现 | `topic-discovery` | 多源检索与校验入库 + 脑暴 idea、新颖性、审计 |
| | 文献综述 | `literature-review` | 整理选题产出为 `literature_review`（不二次检索） |
| | 实验规划 | `experiment-planning` | 可执行实验方案（假设、基线、指标、步骤） |
| | 结果审查 | `auto-review` | 写前：对照 plan 审查实验结果与上传数据 |
| **撰写与审查** | 论文写作 | `paper-writing` | 分节撰写与润色 |
| | 论文审查 | `manuscript-analysis` | 写后：全文投稿前审查 |
| | 图表管理 | `figure-generation` | **Tab：上传图表**（本篇 figure 文件）→ **一键生成**（实验数据出图；仅后者显示「运行」） |
| **资料与设置** | 我的论文 | `my-manuscripts` | 切换、编辑、归档 `paper_manuscript` |
| | 上传文献 | `reference-library` | 上传 / 管理本篇 PDF、BibTeX 等 |
| | 个人中心 | `personal-center` | **Tab：我的信息**（余额/充值/用量）→ **默认配置** → **操作日志**（仅列表） |

- 同一时间 **仅一个二级模块** 为选中态（高亮）；所有一级分组默认常开。
- 各模块共享：**顶栏标题 + 「运行」主按钮**（上传文献、我的论文、个人中心等管理页无运行按钮；默认配置在个人中心 Tab 内保存）；模块内为 **独立表单与说明文案**。

## 4. 全局 UI

### 4.1 顶栏

| 元素 | 说明 |
|------|------|
| Logo + **ARIS Desktop** | 产品标识 |
| **Research workflows** | 产品副标题 |
| **运行** | 主操作按钮（Primary）；根据当前模块配置 **启动该阶段工作流** |

### 4.2 全局系统提示（参考文献门禁）

当门禁开启时，模块内容区顶部展示 **黄色提示条**（不可忽略）：

> **参考文献门禁已启用**：未验证文献不能进入最终引用、BibTeX 或论文正文。

| 规则 | 说明 |
|------|------|
| 验证来源 | 对接配置中的文献 API（如 arxiv、openalex、semantic-scholar） |
| 未通过 | 不得写入引用列表、BibTeX、论文正文 |
| 目的 | 防止 AI **伪造文献**（幻觉引用） |

## 5. 模块：选题发现（与界面一致）

### 5.1 模块标题与描述

- **标题**：选题发现（顶栏与侧栏一致）  
- **描述**：多源检索与校验入库，脑暴 idea 与新颖性检查；完成后顶栏继续 **生成文献综述**（实验方案在「实验规划」）。

### 5.2 表单字段

| 字段名 | 必填 | 控件类型 | 默认值 / 占位 | 产品说明 |
|--------|------|----------|---------------|----------|
| **学科** | 否 | 下拉 | 默认与个人中心「默认配置」一致（如计算机 / 人工智能） | 对齐 `paper_ref_discipline`；影响默认文献源与 venue 关联 |
| **研究方向 / 检索主题** | 是 * | 多行文本 | 研究主题、问题或关键词 | 同时作为多源检索 query 依据 |
| **目标会议/期刊** | 否 | 单行文本 | `NeurIPS/ICLR/ICML` | **风格约束**：贡献类型、实验严谨度、写作调性按目标 venue 调节 |
| **文献来源** | 是 * | 多选 | 默认 arXiv / OpenAlex / Semantic Scholar | **仅此模块**发起多源检索，结果写入 `paper_manuscript_literature_hit` |
| **上传文献** | 否 | 复选框（选题内） | 默认不勾选 | 读本篇「上传文献」上传文件作模型语料（`user_library`，非 API 检索）；勾选时至少 1 篇已上传 |
| **执行强度** | 否 | 下拉 | 默认 **Balanced（平衡）** | 检索条数、脑暴轮数、计划深度 |
| **审计等级** | 否 | 下拉 | 默认 **Polished（精修）** | 控制门禁严格度，包含：**citation audit（引用审查）**、**claim audit（断言审查）**、**kill argument（反驳/杀论点审查）** |
| **人工检查点** | 否 | 复选框 | 默认 **勾选** | 在关键阶段 **暂停**，等待用户确认后再继续 |

### 5.3 运行行为（产品预期）

用户点击 **运行** 后：

1. 校验 **研究方向** 非空。  
2. 按 **文献来源** 多源检索、校验并 **入库**（`retrieve` 阶段）。  
3. 生成 **候选 idea 列表** 并做 **新颖性检查**（基于刚入库语料）。  
4. 执行 **选题断言初 audit**；**不在此步** 生成实验计划。  
5. 若开启 **人工检查点**，在 **新颖性检查** 后暂停，用户确认后继续 audit。  
6. 选题 run **完成后**，顶栏主按钮变为 **「生成文献综述」**（跳转并运行文献综述模块，仍不二次检索）。  
7. 审计等级作用于选题断言，**不替代** 文献综述模块的引用门禁产出。

### 5.4 预期产出（示例）

| 产物 | 说明 |
|------|------|
| 候选选题报告 | 排序后的 idea 列表及依据 |
| 新颖性结论 | 与已有工作的区分点 |
| 已验证文献语料 | 写入 `paper_manuscript_literature_hit`，供 **文献综述** 只读使用 |
| （下一步）文献综述 | 顶栏 **生成文献综述** 或进入文献综述模块运行 |

### 5.5 模块：文献综述（与界面一致）

- **标题**：整理选题产出 → 一篇综述  
- **前置条件**：当前论文 **选题发现 run 已完成**（retrieve、idea、新颖性、audit）。  
- **界面形态**：上方 **只读展示** 选题 artifact（方向、语料统计、idea/新颖性；实验规划摘要若有）；下方 **成稿方式**（分节结构、纳入哪些块、写作深度与引用审计）。**无** 第二套检索表单。  
- **运行行为**：合并 `paper_manuscript_literature_hit` + 选题产出 → `paper_output_literature_review`（领域归纳 + 定位 + gap + 引用表），供论文写作 Related Work 引用。  
- **续跑**：综述生成完成后，在 **文献综述** 页顶栏主按钮变为 **「生成实验计划」**，跳转 **实验规划** 并运行（不在选题发现内出 plan）。

## 6. 其他模块（产品能力摘要）

> 以下与主导航一致；桌面端各模块应提供与「选题发现」同级别的 **配置区 + 运行 + 门禁提示**（具体字段可在迭代中按 ARIS 工作流扩展，此处为产品能力边界）。

| 模块 | 用户目标 | 核心能力 |
|------|----------|----------|
| **文献综述** | 写 Related Work | **合并选题整轮产出**成一篇 `literature_review`（只读展示 + 成稿选项，不重复检索） |
| **实验规划** | 可执行的实验方案 | 假设、基线、指标、资源与步骤 |
| **结果审查** | 提高录用概率 | 多轮审稿式批评、修改建议、分数/弱项跟踪 |
| **论文写作** | 成稿 | 大纲 → 分节写作 → 编译；引用经门禁校验 |
| **图表管理** | 论文级 figure | 上传 PNG/PDF/SVG 等；或在一键生成 Tab 自实验数据生成图表资产 |
| **上传文献** | 自备文献库 | 上传 PDF / BibTeX，编辑标题与备注，按篇论文隔离 |
| **个人中心** | 账号与偏好 | **我的信息**（余额、充值、套餐用量、Token 动态）、**默认配置**（对应 `paper_user_preference`）、**操作日志**（纯列表） |

## 7. 核心机制（跨模块）

### 7.1 参考文献门禁

| 项 | 说明 |
|----|------|
| 状态 | 默认 **启用**（界面显式提示） |
| 验证 | 文献必须在配置源中 **可查到** |
| 拦截点 | 引用块、BibTeX、正文 `\cite` 等等价环节 |

### 7.2 审计等级（以 Polished 为例）

| 审计项 | 说明 |
|--------|------|
| Citation audit | 引用是否与论断匹配、是否存在未验证引用 |
| Claim audit | 结论是否有实验/文献支撑 |
| Kill argument | 模拟严苛审稿人攻击逻辑链 |

### 7.3 人工检查点

| 项 | 说明 |
|----|------|
| 默认 | 开启 |
| 行为 | 工作流在关键阶段 **阻塞**，展示中间产物，用户 **确认 / 修改 / 终止** 后继续 |
| 目的 | 明确 **人是科研主体**，降低学术不端与失控风险 |

### 7.4 目标会议/期刊约束

- 输入示例：`NeurIPS/ICLR/ICML`  
- 影响：写作风格、实验完整度预期、贡献表述方式、审查 rubric。

## 9. 非功能需求（产品层）

| 类别 | 要求 |
|------|------|
| **部署形态** | 桌面端；支持本地运行，敏感数据可不出本机（视默认配置与 runtime 而定） |
| **可追溯** | 中间产物、引用来源可复查 |
| **可中断** | 长任务可停；人工检查点可介入 |
| **Provider** | 支持配置第三方 API / 自定义 Base URL（如 CC-Switch 场景） |
| **算力** | 实验相关阶段可对接远程 GPU（默认配置或 `paper_manuscript_runtime` 中定义） |

## 10. 数据模型（MySQL）

| 脚本 | 说明 |
|------|------|
| `docs/migrations/20261005_paper_workflow_schema.sql` | **Paper Agent 唯一 DDL**（见下表架构） |

**我的论文**：`paper_manuscript`（含 `draft_*` 当前正文）。**阶段进度**：由是否存在当前 `paper_output_*` / `draft_*` 推导，无单独 progress 表。**模块产出表**（前缀 `paper_output_*`，均含 `manuscript_id`）：`paper_output_topic` / `paper_output_topic_idea`（选题）、`paper_output_literature_review`（文献综述）、`paper_output_experiment_plan`（实验规划）、`paper_output_experiment_review`（结果审查）；**论文正文草稿**在 **`paper_manuscript.draft_*`**；**论文审查报告**在 **`paper_manuscript_review`**、`paper_output_figure`（图表）。**本篇文献与引用**：`paper_manuscript_literature_hit`、`paper_manuscript_citation_gate`。**其它**：`paper_user_literature`、`paper_ref_*`、`paper_llm_*`、`paper_llm_call_logs`、`paper_operation_log`。

**LLM 路由**：`paper_llm_workflow_binding` / `paper_llm_prompt_template`；解析顺序：本篇 `manuscript_id` → `user_id` → `user_id=0`。`paper_llm_call_logs` 按 `manuscript_id` + `module_code` 记调用。
