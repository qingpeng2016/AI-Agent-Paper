# ARIS Research Desktop — 产品说明

> 本文档依据 **ARIS Desktop** 界面（Research workflows）整理，用于产品、设计、研发对齐。描述范围与当前桌面端展示 **一致**。

---

## 1. 产品概览

| 项 | 说明 |
|----|------|
| **产品名称** | ARIS Desktop |
| **副标题** | Research workflows |
| **产品类型** | 本地化科研 AI Agent **工作台**（桌面客户端） |
| **一句话** | 覆盖「选题 → 文献 → 实验 → 审查 → 写作 → 图表」的 **顶会导向** 科研全流程，强调 **可验证引用** 与 **人机协同**，而非代写/降重工具。 |
| **典型用户** | 攻读 ML/NLP 等方向的 **硕士、博士、高校/企业科研人员**，目标投稿 **NeurIPS / ICLR / ICML** 等顶会。 |

---

## 2. 产品定位与边界

### 2.1 做什么

- 在 **真实学术数据源** 约束下，辅助完成科研各阶段产出（想法、综述、实验计划、稿件、图表等）。
- 通过 **参考文献门禁**、**审计等级**、**人工检查点**，降低 **引用幻觉、断言不实、逻辑漏洞** 等致命风险。
- 用户是 **科研主体**；产品是 **高阶助手 + 工作流引擎**，关键节点可暂停等人确认。

### 2.2 不做什么

- 不定位为「论文降重 / 降 AI 率 / 排版急救」类工具。
- 不承诺绕过查重或替代作者学术责任。
- 未经验证的文献 **不得** 进入最终引用、BibTeX 或正文（系统强制）。

---

## 3. 信息架构（主导航）

左侧固定 **七项** 工作流模块，顺序如下：

| 序号 | 导航名称 | 模块 ID（建议） | 说明（产品层） |
|------|----------|-----------------|----------------|
| 1 | **选题发现** | `topic-discovery` | 根据研究方向生成候选想法，新颖性检查，并创建实验计划 |
| 2 | **文献综述** | `literature-review` | 基于配置的数据源检索、归纳与结构化综述 |
| 3 | **实验规划** | `experiment-planning` | 实验设计、指标、对照与实施计划 |
| 4 | **自动审查** | `auto-review` | 对稿件/方案做多轮审查与改进（含对抗式审稿逻辑） |
| 5 | **论文写作** | `paper-writing` | 按目标 venue 风格撰写与润色 LaTeX/稿件链路 |
| 6 | **图表生成** | `figure-generation` | 基于实验数据或规划生成论文图表 |
| 7 | **环境配置** | `environment` | 模型、API、数据源、本地/远程 GPU 等运行环境 |

- 同一时间 **仅一个模块** 为选中态（高亮）。
- 各模块共享：**顶栏品牌区 + 「运行」主按钮**；模块内为 **独立表单与说明文案**。

## 4. 全局 UI

### 4.1 顶栏

| 元素 | 说明 |
|------|------|
| Logo + **ARIS Desktop** | 产品标识 |
| **Research workflows** | 产品副标题 |
| **运行** | 主操作按钮（Primary）；根据当前模块配置 **启动该阶段工作流** |

### 4.2 全局系统提示（参考文献门禁）

当门禁开启时，模块内容区顶部展示 **黄色提示条**（不可忽略）：

> **参考文献门禁已启用**：未验证文献不能进入最终引用、BibTeX 或论文正文。

| 规则 | 说明 |
|------|------|
| 验证来源 | 对接配置中的文献 API（如 arxiv、openalex、semantic-scholar） |
| 未通过 | 不得写入引用列表、BibTeX、论文正文 |
| 目的 | 防止 AI **伪造文献**（幻觉引用） |

## 5. 模块：选题发现（与界面一致）

### 5.1 模块标题与描述

- **标题**：选题发现  
- **描述**：根据研究方向生成候选想法，进行新颖性检查，并创建实验计划。

### 5.2 表单字段

| 字段名 | 必填 | 控件类型 | 默认值 / 占位 | 产品说明 |
|--------|------|----------|---------------|----------|
| **研究方向** | 是 * | 多行文本 | 占位：请输入你的研究领域、问题或关键词 | 驱动检索、脑暴与新颖性检查的核心输入 |
| **目标会议/期刊** | 否 | 单行文本 | `NeurIPS/ICLR/ICML` | **风格约束**：贡献类型、实验严谨度、写作调性按目标 venue 调节 |
| **文献来源** | 否 | 单行文本 | `arxiv, openalex, semantic-scholar` | 逗号分隔的数据源列表；仅从这些渠道拉取 **可验证** 文献 |
| **执行强度** | 否 | 下拉 | 默认 **Balanced（平衡）** | 控制检索数量、迭代轮数、输出深度（如：更快 / 平衡 / 更深） |
| **审计等级** | 否 | 下拉 | 默认 **Polished（精修）** | 控制门禁严格度，包含：**citation audit（引用审查）**、**claim audit（断言审查）**、**kill argument（反驳/杀论点审查）** |
| **人工检查点** | 否 | 复选框 | 默认 **勾选** | 在关键阶段 **暂停**，等待用户确认后再继续 |

### 5.3 运行行为（产品预期）

用户点击 **运行** 后：

1. 校验 **研究方向** 非空。  
2. 按 **文献来源** 检索与归纳。  
3. 生成 **候选 idea 列表**，并对每条做 **新颖性检查**。  
4. 输出 **实验计划** 草案。  
5. 若开启 **人工检查点**，在预设节点弹出/展示待确认内容，用户确认后继续。  
6. 全程遵守 **参考文献门禁**；审计等级决定审查深度。

### 5.4 预期产出（示例）

| 产物 | 说明 |
|------|------|
| 候选选题报告 | 排序后的 idea 列表及依据 |
| 新颖性结论 | 与已有工作的区分点 |
| 实验计划 | 可交给「实验规划 / 实验执行」模块的输入 |

## 6. 其他模块（产品能力摘要）

> 以下与主导航一致；桌面端各模块应提供与「选题发现」同级别的 **配置区 + 运行 + 门禁提示**（具体字段可在迭代中按 ARIS 工作流扩展，此处为产品能力边界）。

| 模块 | 用户目标 | 核心能力 |
|------|----------|----------|
| **文献综述** | 快速掌握领域 | 主题检索、结构化综述、可追溯引用 |
| **实验规划** | 可执行的实验方案 | 假设、基线、指标、资源与步骤 |
| **自动审查** | 提高录用概率 | 多轮审稿式批评、修改建议、分数/弱项跟踪 |
| **论文写作** | 成稿 | 大纲 → 分节写作 → 编译；引用经门禁校验 |
| **图表生成** | 论文级 figure | 自实验数据或规划生成图表资产 |
| **环境配置** | 可重复运行 | 模型 Provider、Base URL、API Key、本地/远程算力、CC-Switch 等 |

## 7. 核心机制（跨模块）

### 7.1 参考文献门禁

| 项 | 说明 |
|----|------|
| 状态 | 默认 **启用**（界面显式提示） |
| 验证 | 文献必须在配置源中 **可查到** |
| 拦截点 | 引用块、BibTeX、正文 `\cite` 等等价环节 |

### 7.2 审计等级（以 Polished 为例）

| 审计项 | 说明 |
|--------|------|
| Citation audit | 引用是否与论断匹配、是否存在未验证引用 |
| Claim audit | 结论是否有实验/文献支撑 |
| Kill argument | 模拟严苛审稿人攻击逻辑链 |

### 7.3 人工检查点

| 项 | 说明 |
|----|------|
| 默认 | 开启 |
| 行为 | 工作流在关键阶段 **阻塞**，展示中间产物，用户 **确认 / 修改 / 终止** 后继续 |
| 目的 | 明确 **人是科研主体**，降低学术不端与失控风险 |

### 7.4 目标会议/期刊约束

- 输入示例：`NeurIPS/ICLR/ICML`  
- 影响：写作风格、实验完整度预期、贡献表述方式、审查 rubric。

|--------------|--------|------|------|
| 更快 | 少 | 少 | 精简 |

## 9. 非功能需求（产品层）

| 类别 | 要求 |
|------|------|
| **部署形态** | 桌面端；支持本地运行，敏感数据可不出本机（视环境配置而定） |
| **可追溯** | 中间产物、引用来源可复查 |
| **可中断** | 长任务可停；人工检查点可介入 |
| **Provider** | 支持配置第三方 API / 自定义 Base URL（如 CC-Switch 场景） |
| **算力** | 实验相关阶段可对接远程 GPU（环境配置中定义） |
