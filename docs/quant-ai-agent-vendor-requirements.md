# 策略挖掘 AI — 核心采购要求

## 1. 策略挖掘能力

| 要求 | 验收标准（什么叫达标） |
|------|------------------------|
| **闭环多轮挖掘** | 同一项目内，至少完成 **≥3 轮**「提出改动 → 改代码/参数 → 再回测 → 写本轮结论」；每轮有 **独立编号或时间戳**，不能只有一次 LLM 回复就结束。 |
| **未达标须如实终止** | 当 **回测指标未达到项目目标**（如 Sharpe&lt;1.0）时，系统 **明确 verdict=不采纳/继续挖/终止**，并写 **结构原因**（如单边熊市亏损），禁止仍标「推荐上线」。 |
| **可交付物齐全** | 每个定稿或候选 run 至少包含：**策略源码或插件文件**、**回测配置说明**（费、滑点、区间）、**指标表**、**净值曲线**、**实验摘要 Markdown 或等价报告**；均可下载或 API 拉取。 |
| **历史 run 可比** | 同一项目可列出 **多版本回测**（如 v7/v8）；点选任一条可看到 **当时指标与曲线**，便于对比迭代效果。 |

---

## 2. 多模态对抗与结果校验（必达，缺一视为不合格）

| 要求 | 验收标准（什么叫达标） |
|------|------------------------|
| **生成与审查分离** | 写策略代码的模型/Agent 与 **审代码的模型/Agent 不是同一调用链自评**；须提供 **审查记录**（谁审、输入文件、输出 decision）。 |
| **审查驳回原因列表** | 审查 **驳回** 时须 **逐条列出 issue**（每条含 **原因类型 + 说明 + 对应代码/逻辑位置**）；UI 或导出报告中有 **完整驳回原因列表**，禁止仅显示「未通过」无明细。 |
| **回测结果独立校验** | 界面展示的 **最大回撤、交易笔数**，须经过 **固定脚本或第二 Agent** 对原始回测输出 **重算或 diff**；校验失败则 **不得展示为已通过**。 |
| **候选策略门禁** | 只有 **审查=通过 且 结果校验=通过** 的 run，才允许标记为 **「候选策略 / 可交接下游」**；否则按钮灰显或状态为 rejected。 |

---

## 3. 多标的

| 要求 | 验收标准（什么叫达标） |
|------|------------------------|
| **分项目隔离** | BTC 项目与黄金项目 **数据、Brief、代码、回测记录互不串线**；打开 A 项目不会出现 B 项目的标的或路径。 |
| **标的显式配置** | 创建/编辑项目时必须 **选定标的或合约类型**（如 BTC-USDT 永续、XAU 连续）。 |
| **扩展标的** | 除 BTC、黄金外其他市场（A 股、美股等）。 |

---

## 4. 数据源接入（回测与上盘）

| 要求 | 验收标准（什么叫达标） |
|------|------------------------|
| **支持多类数据源** | 回测所需数据不限于单一内置库；至少支持 **多种接入方式**（如：**REST/API 行情**、**客户上传文件** CSV/Parquet、**对象存储路径**、**数据库只读连接** 等中的 **≥2 类**），并在文档中列 **完整接入清单**。 |
| **数据源字段与结构体** | 支持 **动态修改** 接入的数据源 **字段和结构体**。 |
| **项目绑定数据源** | 每个项目须 **显式选择数据源**，便于复现。 |
| **验收演示** | 现场演示：**同一平台** 上至少 **两个不同数据源** 各完成 **一次成功回测**。 |

---

## 5. 模拟盘与实盘（挖掘后上盘）

| 要求 | 验收标准（什么叫达标） |
|------|------------------------|
| **模拟盘上盘与门禁** | 仅 **§2 通过** 的候选可挂 **模拟盘**，绑定 **策略版本 + run ID**；未通过 **不得** 上模拟盘/实盘；**模拟盘 → 实盘** 须同版本或重新签收。 |
| **模拟盘运行可观测** | 模拟盘至少展示：**持仓、委托/成交（或信号）、虚拟权益、当日盈亏**；策略与回测使用 **同一套标的与合约定义**（§3）。 |
| **候选策略可上实盘** | 将 **指定版本** 候选接到 **实盘**（交易所/券商 API 等）；账户单独配置，**密钥不进日志/Prompt**。 |
| **回测与上盘可追溯** | 模拟盘/实盘页面可反查：**来自哪次挖掘 run、哪版代码、哪段回测区间、哪一数据源**（§4）；便于排查「回测好、上盘差」。 |
| **全链路与对接说明** | 须提供 **从候选 → 模拟盘 → 实盘** 的 **完整可演示路径**；内置、外链或我方对接均须 **书面接口/导出规范**（策略包、manifest、版本 ID），不得只交付挖掘不含上盘。 |

---

## 6. 验证

| 要求 | 验收标准（什么叫达标） |
|------|------------------------|
 **验收用例 A（BTC）** | BTC 项目：**挖掘闭环** + **审查与校验通过** + **指定数据源回测** + **候选策略成功跑模拟盘**。 |
| **验收用例 B（黄金）** | 黄金项目：同上，manifest **标的为黄金**，**数据源与 BTC 项目隔离**。 |
| **验收用例 C（负例）** | **故意错误的样例** 须 **驳回**，且 **不能** 进入模拟盘/实盘。 |
| **验收用例 D（数据源）** | 演示 **第二数据源** 接入并完成回测（见 §4 最后一条）；仅单一硬编码数据源则 **本条不通过**。 |
| **验收用例 E（实盘，必达）** | 演示 **测试网或小额实盘** 完整下单链路：**信号 → 风控（若有）→ 下单 → 回报/对账**；仅模拟盘、无实盘能力则 **整体验收不通过**。 |
